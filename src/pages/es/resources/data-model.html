Modelo de datos de las entradas de tiempo

Qué contiene una entrada de tiempo en TIMEperative, qué reglas sigue y cómo se relaciona con los proyectos, la facturación y el registro de auditoría.

Acerca de esta referencia

Esta página es para quienes leen las exportaciones de TIMEperative, las cargan en otro sistema o las revisan en una auditoría. Describe los datos tal como la aplicación los guarda hoy, versión 0.1.0-alpha.16, contrastados con el código de la aplicación el 21 de octubre de 2026. TIMEperative está en acceso anticipado, así que pueden añadirse campos; esta página cambia con ellos.

Cada instalación guarda sus datos en una base de datos en el dispositivo, en Windows o en Android. No hay ningún servidor de TIMEperative. Los datos solo salen del dispositivo cuando los exportas o envías entradas a través de TIMEperative Cloud Sync, un complemento independiente que tu organización instala y configura. La política de privacidad enumera cada conexión.

La entrada de tiempo es el centro. Todo lo demás la describe o se crea a partir de ella.

La aplicación también guarda las etiquetas de una entrada y el comentario de su último cambio de estado. Hoy no forman parte de la exportación.

Tipos de entrada

  • actual: tiempo trabajado. Solo las entradas reales cuentan como tiempo trabajado, pasan a facturación y se envían a través de Cloud Sync.
  • planned: tiempo programado, por ejemplo desde la planificación o desde un calendario.
  • requested: tiempo solicitado pero no confirmado, por ejemplo una invitación a una reunión aún no aceptada.

El tipo de una entrada no cambia. Llevar a cabo un plan crea una nueva entrada real que apunta al plan, y el plan queda como estaba. Las entradas importadas de un calendario guardan la referencia del evento, así que importar de nuevo las actualiza en lugar de añadir copias.

Estado y bloqueo

Una entrada nueva es un borrador. Solo los borradores se pueden cambiar; para cambiar una entrada en otro estado, primero vuelve a borrador.

DeASignificado
draftsubmittedLa persona presenta la entrada.
submittedapprovedLa entrada se aprueba.
submittedrejectedLa entrada se rechaza, con un comentario opcional.
submittedinquiryUna consulta sobre la entrada, con un comentario opcional.
submitted, approved, rejected, inquirydraftLa entrada se vuelve a abrir para cambiarla.
approvedconvertedSolo mediante la facturación: la entrada pasó a formar parte de una entrada facturable. Al quitar esa entrada facturable, vuelve a approved.

Cada cambio de estado escribe un registro de auditoría.

Estado de cumplimiento

El estado de cumplimiento indica si la descripción basta para facturar. Una descripción vacía es siempre description_missing. Una descripción rellenada es compliant, salvo que alguien la haya marcado como unclear o misleading.

Eliminar

  • Eliminar una entrada rellena deletedAt; la entrada se puede restaurar. La exportación de entradas de tiempo deja fuera las entradas eliminadas.
  • Una entrada eliminada puede después eliminarse para siempre. Su último estado queda en el registro de auditoría.
  • Una entrada convertida no se puede eliminar, porque una entrada facturable hace referencia a ella.

Proyectos y actividades

Un proyecto tiene un nombre, un tipo, un nombre de cliente opcional, un color y un ajuste que indica si su tiempo es facturable por defecto. Su tipo es work, private, public_holiday, vacation o absence.

Una actividad pertenece exactamente a un proyecto. Las actividades se pueden anidar bajo una actividad superior para formar un desglose del trabajo, llevar un código y anular el ajuste de facturación del proyecto.

Etiquetas

Una etiqueta tiene un nombre, único en la instalación, y un color. Las entradas y las etiquetas se relacionan de muchos a muchos.

Lugares

Un lugar tiene un nombre, un tipo, una dirección opcional con país y unas coordenadas opcionales. Su tipo es home, remote, office, customer, collection_point, work_area, transit, other o unclassified. Un lugar puede pertenecer a una persona o compartirse en la instalación.

Entradas facturables

La facturación convierte las entradas reales aprobadas en entradas facturables. Las agrupa por día, proyecto y persona y aplica las reglas de facturación, que pueden redondear y limitar el tiempo. Las entradas usadas pasan a converted.

Exportar para facturar bloquea las entradas facturables que marca, para que nada se facture dos veces. Una entrada facturable bloqueada se puede desbloquear, y vuelve a ser open.

Registro de auditoría

Cada cambio escribe un registro de auditoría, y la exportación del registro de auditoría los contiene con estas columnas:

  • id: el número del registro.
  • entity y entityId: qué se cambió, por ejemplo una entrada de tiempo y su número.
  • action: create, update, delete, restore, purge (eliminada para siempre) o status_change.
  • changes: en JSON, el valor anterior y el nuevo de cada campo cambiado; en una entrada nueva o eliminada para siempre, su estado completo.
  • actor: el nombre de la persona que hizo el cambio.
  • atUtc: cuándo, como instante.

Envío a través de Cloud Sync

A través de TIMEperative Cloud Sync solo se envían las entradas reales aprobadas que no estén eliminadas. Para cada entrada, la aplicación guarda si está en espera, si llegó o si falló, con el error. Las entradas que llegaron no se vuelven a enviar y, cuando el Cloud Sync lo admite, reconoce una entrada que ya tiene, así que volver a enviar no añade ninguna copia.

Exportaciones hoy

  • Las entradas de tiempo, las entradas facturables y el registro de auditoría se exportan como CSV: UTF-8, separado por comas, una fila de encabezado y valores entre comillas donde hace falta.
  • La exportación de entradas de tiempo contiene las entradas que muestra la lista, con sus filtros.
  • Hasta ahora, las columnas nuevas se han añadido al final, así que los programas que leen las columnas por su posición siguen funcionando.
  • Los identificadores solo son únicos dentro de una instalación. Dos instalaciones numeran sus entradas de forma independiente.
