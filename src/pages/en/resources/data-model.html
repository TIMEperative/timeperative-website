Time entry data model

What a time entry in TIMEperative holds, which rules it follows and how it relates to projects, billing and the audit trail.

About this reference

This page is for people who read TIMEperative's exports, load them into another system, or check them in an audit. It describes the data as the app keeps it today, version 0.1.0-alpha.16, checked against the app's code on 21 October 2026. TIMEperative is in early access, so fields may be added; this page changes with them.

Each installation keeps its data in one database on the device, on Windows or on Android. There is no TIMEperative server. Data leaves the device only when you export it or send entries to your TIMEperative Cloud Hub, which needs the separate TIMEperative.sync app. The privacy policy lists every connection.

Overview

The time entry is the centre. Everything else either describes it or is made from it.

RecordRelation to the time entry
PersonEvery entry belongs to exactly one person.
ProjectEvery entry is booked on exactly one project.
ActivityAn entry may name one activity of its project; some projects require one.
TagAn entry carries any number of tags; a tag is used by any number of entries.
PlaceAn entry may name the place where the work was done.
Planned entryAn actual entry may point to the planned entry it carries out; one plan can be carried out by several actual entries.
Billable entryMade from approved entries; one billable entry covers one or more entries, and each entry belongs to at most one billable entry.
Audit recordCreating, changing, deleting, restoring and changing the status of an entry each write an audit record.
Cloud Hub linkWhen an entry is sent to the Cloud Hub, one link records whether it arrived.

Entry types

  • actual: time that was worked. Only actual entries count as worked time, go to billing and are sent to the Cloud Hub.
  • planned: time that is scheduled, for example from planning or from a calendar.
  • requested: time that was asked for but not committed, for example a meeting invitation not yet accepted.

The type of an entry does not change. Carrying out a plan creates a new actual entry that points to the plan, and the plan stays as it was. Entries imported from a calendar keep the event's reference, so importing again updates them instead of adding copies.

Status and locking

A new entry is a draft. Only drafts can be changed; to change an entry in another status, it goes back to draft first.

FromToMeaning
draftsubmittedThe person hands the entry in.
submittedapprovedThe entry is accepted.
submittedrejectedThe entry is not accepted, optionally with a comment.
submittedinquiryA question about the entry, optionally with a comment.
submitted, approved, rejected, inquirydraftThe entry is opened again for changes.
approvedconvertedOnly through billing: the entry became part of a billable entry. Removing that billable entry returns it to approved.

Every status change writes an audit record.

Compliance status

The compliance status says whether the description is good enough to bill. An empty description is always description_missing. A filled description is compliant, unless someone marked it unclear or misleading.

Deleting

  • Deleting an entry sets deletedAt; the entry can be restored. The time entries export leaves deleted entries out.
  • An entry that was deleted can then be deleted forever. Its last state stays in the audit trail.
  • A converted entry cannot be deleted, because a billable entry refers to it.

Projects and activities

A project has a name, a type, an optional customer name, a colour and a setting for whether its time is billable by default. Its type is one of work, private, public_holiday, vacation or absence.

An activity belongs to exactly one project. Activities can be nested under a parent activity to form a work breakdown, carry a code, and override the project's billable setting.

Tags

A tag has a name, unique in the installation, and a colour. Entries and tags are linked many to many.

Places

A place has a name, a kind, an optional address with country, and optional coordinates. Its kind is one of home, remote, office, customer, collection_point, work_area, transit, other or unclassified. A place can belong to one person or be shared in the installation.

Billable entries

Billing turns approved actual entries into billable entries. It groups them by day, project and person and applies the billing rules, which can round and cap the time. The entries it used become converted.

ColumnValues and meaning
idThe billable entry's number in this installation.
dateThe day.
userThe person's name.
projectThe project's name.
descriptionThe text for the invoice, made from the entries' descriptions or written by hand.
durationMinutes, durationHoursThe billable length after the rules.
statusopen or exported_for_billing.
batchIdThe export that locked it, B- followed by the export's date and time in UTC, for example B-20261021-073000.
exportedAtWhen it was exported for billing.
adjustmentsWhat the rules changed.
linkedEntryIdsThe numbers of the time entries it was made from, separated by spaces.

Exporting for billing locks the billable entries it marks, so nothing is billed twice. A locked billable entry can be unlocked, which makes it open again.

Audit trail

Every change writes one audit record, and the audit trail export holds them with these columns:

  • id: the record's number.
  • entity and entityId: what was changed, for example a time entry and its number.
  • action: create, update, delete, restore, purge (deleted forever) or status_change.
  • changes: as JSON, the old and the new value of each changed field; for a new or a forever deleted entry, its whole state.
  • actor: the name of the person who made the change.
  • atUtc: when, as a point in time.

Sending to the Cloud Hub

Only approved actual entries that are not deleted are sent to your TIMEperative Cloud Hub. For each entry the app keeps whether it is waiting, arrived or failed, with the error. Entries that arrived are not sent again, and where the Cloud Hub supports it, it recognises an entry it already has, so sending again adds no copy.

Exports today

  • Time entries, billable entries and the audit trail export as CSV: UTF-8, comma separated, one header row, values in quotes where they need them.
  • The time entries export holds the entries the list shows, with its filters.
  • New columns have so far been added at the end, so readers that address columns by position keep working.
  • Identifiers are unique within one installation only. Two installations number their entries independently.
