Modèle de données des entrées de temps

Ce que contient une entrée de temps dans TIMEperative, les règles qu'elle suit et ses liens avec les projets, la facturation et la piste d'audit.

À propos de cette référence

Cette page s'adresse aux personnes qui lisent les exportations de TIMEperative, les chargent dans un autre système ou les contrôlent lors d'un audit. Elle décrit les données telles que l'application les conserve aujourd'hui, version 0.1.0-alpha.16, vérifiées par rapport au code de l'application le 21 octobre 2026. TIMEperative est en accès anticipé : des champs peuvent s'ajouter, et cette page évolue avec eux.

Chaque installation conserve ses données dans une base de données sur l'appareil, sous Windows ou sous Android. Il n'existe pas de serveur TIMEperative. Les données ne quittent l'appareil que lorsque vous les exportez ou envoyez des entrées via TIMEperative Cloud Sync, un module complémentaire distinct que votre organisation installe et configure. La politique de confidentialité recense chaque connexion.

Types d'entrée

  • actual : temps travaillé. Seules les entrées réelles comptent comme temps travaillé, passent en facturation et sont envoyées via Cloud Sync.
  • planned : temps prévu, par exemple issu de la planification ou d'un calendrier.
  • requested : temps demandé mais pas confirmé, par exemple une invitation à une réunion pas encore acceptée.

Le type d'une entrée ne change pas. Réaliser un plan crée une nouvelle entrée réelle qui renvoie au plan, et le plan reste tel quel. Les entrées importées d'un calendrier gardent la référence de l'événement : une nouvelle importation les met à jour au lieu d'ajouter des copies.

Statut et verrouillage

Une nouvelle entrée est un brouillon. Seuls les brouillons peuvent être modifiés ; pour modifier une entrée dans un autre statut, elle repasse d'abord en brouillon.

DeVersSignification
draftsubmittedLa personne soumet l'entrée.
submittedapprovedL'entrée est approuvée.
submittedrejectedL'entrée est refusée, avec un commentaire facultatif.
submittedinquiryUne question sur l'entrée, avec un commentaire facultatif.
submitted, approved, rejected, inquirydraftL'entrée est rouverte pour être modifiée.
approvedconvertedUniquement par la facturation : l'entrée fait désormais partie d'une entrée facturable. Supprimer cette entrée facturable la ramène à approved.

Chaque changement de statut écrit un enregistrement d'audit.

Statut de conformité

Le statut de conformité indique si la description suffit pour facturer. Une description vide est toujours description_missing. Une description remplie est compliant, sauf si quelqu'un l'a marquée unclear ou misleading.

Suppression

  • Supprimer une entrée renseigne deletedAt ; l'entrée peut être restaurée. L'exportation des entrées de temps omet les entrées supprimées.
  • Une entrée supprimée peut ensuite être supprimée définitivement. Son dernier état reste dans la piste d'audit.
  • Une entrée convertie ne peut pas être supprimée, car une entrée facturable y fait référence.

Projets et activités

Un projet a un nom, un type, un nom de client facultatif, une couleur et un réglage indiquant si son temps est facturable par défaut. Son type est work, private, public_holiday, vacation ou absence.

Une activité appartient à exactement un projet. Les activités peuvent être imbriquées sous une activité parente pour former un découpage du travail, porter un code et remplacer le réglage de facturation du projet.

Étiquettes

Une étiquette a un nom, unique dans l'installation, et une couleur. Les entrées et les étiquettes sont liées de plusieurs à plusieurs.

Lieux

Un lieu a un nom, un type, une adresse facultative avec le pays et des coordonnées facultatives. Son type est home, remote, office, customer, collection_point, work_area, transit, other ou unclassified. Un lieu peut appartenir à une personne ou être partagé dans l'installation.

Entrées facturables

La facturation transforme les entrées réelles approuvées en entrées facturables. Elle les regroupe par jour, projet et personne et applique les règles de facturation, qui peuvent arrondir et plafonner le temps. Les entrées utilisées deviennent converted.

L'exportation pour la facturation verrouille les entrées facturables qu'elle marque, afin que rien ne soit facturé deux fois. Une entrée facturable verrouillée peut être déverrouillée, ce qui la remet à open.

Piste d'audit

Chaque modification écrit un enregistrement d'audit, et l'exportation de la piste d'audit les contient avec ces colonnes :

  • id : le numéro de l'enregistrement.
  • entity et entityId : ce qui a été modifié, par exemple une entrée de temps et son numéro.
  • action : create, update, delete, restore, purge (supprimée définitivement) ou status_change.
  • changes : en JSON, l'ancienne et la nouvelle valeur de chaque champ modifié ; pour une entrée nouvelle ou supprimée définitivement, son état complet.
  • actor : le nom de la personne qui a fait la modification.
  • atUtc : quand, sous forme d'instant.

Envoi via Cloud Sync

Seules les entrées réelles approuvées et non supprimées sont envoyées via TIMEperative Cloud Sync. Pour chaque entrée, l'application conserve si elle est en attente, arrivée ou en échec, avec l'erreur. Les entrées arrivées ne sont pas renvoyées, et lorsque le Cloud Sync le permet, il reconnaît une entrée qu'il a déjà : un nouvel envoi n'ajoute donc pas de copie.

Exportations aujourd'hui

  • Les entrées de temps, les entrées facturables et la piste d'audit s'exportent en CSV : UTF-8, séparateur virgule, une ligne d'en-tête, valeurs entre guillemets lorsque c'est nécessaire.
  • L'exportation des entrées de temps contient les entrées que la liste affiche, avec ses filtres.
  • Jusqu'ici, les nouvelles colonnes ont été ajoutées à la fin, si bien que les programmes qui lisent les colonnes par leur position continuent de fonctionner.
  • Les identifiants ne sont uniques qu'au sein d'une installation. Deux installations numérotent leurs entrées indépendamment.
